# AR02 — Separate view state and settings publication

Status: Implemented.

## Planned solution

Publish directory contents without replacing current view preferences. Introduce typed validated settings with atomic replacement; hydrate application state before initial navigation.

## Applied solution

Extracted `SettingsStore` and typed `AppSettings`/`PanelSettings`, backed by Boost.JSON with version/type/range validation and checked exclusive temporary-file replacement. Added `DirectorySnapshot` publication and UI-owned `PanelViewState`; worker contents cannot overwrite newer preferences. Native startup defers navigation until settings are validated and applied. Settings and theme write failures are reported.

## Validation

Native build; AR02 regression (all six orders, delayed refresh, invalid settings, failed replacement cleanup and unsupported version); R29 bindings; all 14 Lua scenarios passed. Logs: `build/architecture-validation/AR02-*.log`.

## Differences from the plan

Kept the existing `Dir` view API through `PanelViewState` inheritance, avoiding a broad consumer rewrite. Selection flags remain in UI entry records pending AR04. Separate theme and settings files each have atomic replacement; they are not a single cross-file transaction. Missing legacy version is treated as version 1.
