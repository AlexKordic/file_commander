# AR06 — Separate operation services from UI

Status: Implemented.

## Planned solution

Introduce typed operation plans, UI-free planners and job interfaces, injected error/event sinks and ID-based controls; move small filesystem mutations behind asynchronous services.

## Applied solution

Extracted a headless `CopyPlanner` and immutable `OperationPlan` with explicit step kinds and named source/destination/link/message fields. The executor interprets typed steps; dialogs adapt plans to preview records. Added injected archive/clipboard services, manager-owned error reporting, ID controls including queued jobs, and a UI-free error-count interface. Directory enumeration returns errors instead of reporting to a global manager. Mkdir, rename and clipboard now run through jobs and post immutable results back with dialog lifetime/generation checks; failed rename rows remain available for retry. A headless operation library/test target links only filesystem support.

## Validation

Headless planner/executor test passes without FTXUI/Lua linkage, including two isolated managers and injected clipboard. Full native suite and all 14 Lua scripts passed. AR06 additionally checks a blocked clipboard worker, UI-returned pending state, queued ID cancellation and dialog destruction before delivery. R06 rename and R24 mkdir feedback regressions were adapted to wait for dispatched completion and passed. Logs: `build/architecture-validation/AR06-*.log`.

## Differences from the plan

Retained a clearly named legacy `DirItem`-to-plan adapter and pointer controls for existing callers/tests; production dialogs construct typed plans and controls have ID entry points. Job detail metadata remains a compatibility view alongside the shared immutable plan. The asynchronous small operations use the existing serial job worker rather than another scheduler. Full build-target reuse and source separation follow in AR09.
