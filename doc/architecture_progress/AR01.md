# AR01 — Retain UI messages across terminal suspension

Status: Implemented.

## Planned solution

Add an application-owned dispatcher with active/suspended/closed states; route worker and timer notifications through injected sinks; drain messages after terminal resumption and reject delivery after close.

## Applied solution

Added an application-owned `UiDispatcher` with retained callbacks, coalesced notifications, suspension and shutdown. Directory workers, file jobs, discovery, search, logging and timers now use injected delivery callbacks. The application drains callbacks on the UI thread after restored-I/O operations resume.

## Validation

Native build and AR01, R25 and R31 regressions passed. All 14 Lua scenarios passed. Logs: `build/architecture-validation/AR01-*.log`. `git diff --check` passed.

## Differences from the plan

The dispatcher wakes its own condition variable; it does not call FTXUI from worker threads. The UI pumps native input at most 16 ms apart. This avoids touching FTXUI sender state while terminal installation or suspension changes its lifetime.
