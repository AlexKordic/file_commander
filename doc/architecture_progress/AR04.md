# AR04 — Bound UI publication and observation costs

Status: Implemented.

## Planned solution

Use keyed selection reconciliation, avoid duplicate active-tab snapshots, publish lightweight job summaries/shared detail, and coalesce watcher refresh work.

## Applied solution

Selection restoration uses hashed stable paths and one statistics pass. Active tab directory storage is moved when switching; metadata synchronization does not copy entries. JobList uses lightweight summaries, caches completed summaries and requests detail only on opening or execution changes. The progress bar renders after releasing the job lock. Watcher batches are merged, ordinary batches read changed metadata on the worker and publish deltas, and overflow/recovery or concurrent invalidation falls back to a full scan.

## Validation

AR04 measured selection reconciliation at 10,000 entries: 1.29 ms; 20,000: 2.65 ms (Debug, local arm64). 100 summaries of a 100,000-item plan: 0.14 ms. Regression guards allow 250 ms per reconciliation and reject quadratic scaling, and verify ordinary watcher changes avoid full scans. Full native suite and all 14 Lua scripts passed, including tabs and watcher scenarios. Logs: `build/architecture-validation/AR04-*.log`.

## Differences from the plan

Explicit new-tab cloning still copies entries once. Sorted delta publication remains O(N log N); directory contents are UI-owned and moved rather than shared mutable storage. Detail snapshots are copied on demand/change; the immutable typed plan boundary follows in AR06. Completed summaries are cached; active summaries are small fresh values.
