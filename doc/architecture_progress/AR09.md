# AR09 — Enforce module, build and test boundaries

Status: Implemented.

## Planned solution

Extract implementations into focused modules and reusable library targets; provide headless core tests, CTest registration, configurable isolated PTY runners and validated dependency revisions.

## Applied solution

Moved application implementations out of `app.hpp` into `app.cpp`; split search, job/error views, settings/palette views and command metadata into focused translation units. CMake now builds shared `fc_core`, `fc_ui` and `fc_lua` libraries, with the executable and regressions reusing those objects. `FC_CORE_ONLY` configures and tests the core without inspecting terminal, Lua, editor or archive-tool checkouts.

Registered native, headless, Lua, negative-control, process-exit, packaging and dependency-rebuild suites with CTest labels. PTY runners accept binary/log paths, isolate settings and fixtures, and allocate per-process debug logs; the smoke target runs the full Lua suite. Added a dependency manifest, Boost checksum and configure/build-time revision validation. The Zig toolchain creates target archives with Zig while LuaJIT generators use the host compiler. [Build boundaries](../build_boundaries.md) documents the supported setup, targets and runtime contracts.

Boundary checks also corrected empty event-sink detachment, removed unused delete destinations, and ensured copy submission acquires archive leases before releasing the planner.

## Validation

All seven native CTest suites passed, including 40 regression cases, the headless contract, 14 Lua scripts, five negative controls, seven process-exit cases, an outside-checkout package run and source-rebuild checks for LuaJIT/7zr/Fresh. Core-only configure/build/test passed with all four non-core source directories set to nonexistent paths. Compile-command inspection confirms 11 core sources have no FTXUI/Lua include paths and the regression target compiles only its own test source. Dependency validation and `git diff --check` passed.

The core and regression suites also passed UBSan. A clean Linux x86-64 Zig build produced static ELF application and core-test binaries; they were not executed on Linux. Logs: `build/architecture-validation/final-native-ctest.log`, `final-ubsan.log`, `final-linux.log` and `AR09-core-only.log`.

## Differences from the plan

Used three concrete libraries instead of introducing separate application/platform libraries: the core enforces the important UI-free service boundary, while panel composition and FTXUI-dependent commands remain in `fc_ui`. Kept source files at the repository root to avoid an unrelated directory migration. Slow dependency-rebuild validation is opt-in and was enabled for the final run.

The dependency setup now uses public pinned sources and an automated bootstrap; see [build boundaries](../build_boundaries.md#reproducible-inputs). Linux verification in this implementation record covers compilation only. At the time of this validation, the Apple ASan runtime hung before `main`; UBSan passed. Later sanitizer results are recorded in [test progress](../test_suite_progress_2026-09-27.md#current-qualification--2026-10-05). A pre-existing cross-build cache retained the old host archiver, so the updated Zig toolchain was verified from a clean build directory.
