# AR05 — Bound retained resources

Status: Implemented.

## Planned solution

Add limits and explicit expiry to history/events/results; use archive leases and an eviction budget; prune consumed Lua events and bound traversal queues/results.

## Applied solution

Added configurable `JobRetention`: 256 completed summaries, 32 detailed jobs / 32 MiB estimated detail payload, 4,096 sequenced transitions, 1,024 global errors and 256 pending submissions. Full queues reject without blocking the UI. Completed details expire with counts retained; errors/cancelled jobs follow the same bounded policy. Event lookup uses a bounded deque with binary cursor lookup and an explicit expiry marker. Lua prunes consumed events and caps unconsumed events at 4,096 with expiry notification. Delete discovery uses a 1,024-entry queue. Archive cache defaults to 16 roots / 256 MiB extracted file bytes and evicts only unpinned roots.

## Validation

AR05 executed 1,000 jobs using small limits and checked summary/detail/error/event bounds, cursor expiry and dismissal. A real archive was replaced with another version; both active leases survived and only released versions were evicted. Full native suite and all 14 Lua scripts passed. Logs: `build/architecture-validation/AR05-*.log`.

## Differences from the plan

Archive limits are soft while leases pin roots; trimming occurs on subsequent cache activity or explicit `trim_cache`, keeping filesystem cleanup off UI publication. Detail bytes estimate owned record/string payload, not allocator overhead. The compatibility history API still returns stopped job handles, but expired handles contain only summary state. Search/frontier limits landed with AR03. Per-job error detail is capped at 1,024 records / 64 KiB per message, while aggregate error counts remain exact.
