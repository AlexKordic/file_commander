# AR08 — Unify commands and application events

Status: Implemented.

## Planned solution

Register handlers and availability once; route palette, shortcut and semantic Lua commands through the same contract; replace concrete-dialog polling with owner-published request events.

## Applied solution

Registered application handlers and availability predicates by stable command ID. Shortcuts, palette and `fc.command`/`fc.cmd` use the same execution and usage-accounting path; panel actions execute directly without synthesizing keys. Moved key bindings out of visual Theme into `KeyBindings`, with command binding references replacing the parallel ID-to-theme mapping. Added a bounded application event stream. CopyPlanner, Find and FileJobs publish request/job events; Lua reads the stream and no longer inspects discovery/search dialog internals.

## Validation

AR08 invokes every catalog command through palette, shortcut and semantic Lua adapters with instrumented handlers, checking identical dispatch and usage; disabled handlers reject execution without counting. A headless planner publishes its own completion ID. Full native suite and all 14 Lua scripts passed. Logs: `build/architecture-validation/AR08-*.log`.

## Differences from the plan

Low-level mouse input, palette activation and repeated Escape handling remain input-adapter responsibilities. Application-owned observation compares panel selection/revision/focus state once per UI pass because FTXUI can change focus internally; Lua no longer reconstructs those changes. Domain worker/job completions, errors and progress originate in their services. Raw key injection remains available for UI tests.
